## The loop

1. `ks gen` — compile the spec, regenerate `gen/`, migrations, clients and this file.
2. `ks check` — build, vet and run the Keystone analyzers; fix every finding.
3. `ks test` — generated policy tests plus yours, against a real Postgres.
4. `ks migrate plan` — see what the schema change costs before applying it.
5. `ks diff --base main` — the behaviour change a human reviews.
